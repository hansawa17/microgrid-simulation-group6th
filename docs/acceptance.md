# 联调与验收记录模板

依据原文第五、六节；另加入协议健壮性测试建议。

- [ ] A/B/C 独立启动，依赖及启动说明可复现。
- [ ] A 读取独立风速、负荷场景；功率目标、动作与实际值区分。
- [ ] A/B/C 各自本地库和界面能显示状态、参数、历史与异常。
- [ ] B 开环不发送控制；闭环目标受设备约束；备用含义可解释。
- [ ] 真 STM32 通过 Wi-Fi 获取状态/目标，返回控制动作；上位机串口参数回写成功。
- [ ] 无风、正常风速、切出风速、低/高负荷、柴发能力不足均有可解释结果。
- [ ] 超时、断线、重连、重复/乱序命令、非法值、TCP 分包/粘包可识别并记录。
- [ ] 安全动作优先级和失联行为符合最终共同约定。
- [ ] 历史能复原状态→目标→动作→结果，sim_time 与接收时间不混用。

每个案例记录：日期、提交 SHA、设备/固件、配置（不含密码）、输入场景、预期、实际、截图/日志路径、执行人、是否通过。
任何示例数据或 mock 结果必须注明；不以单元测试通过替代真实硬件联调。

A 的 PC 软件故障复现入口位于 `scripts/fault_injection/`：协议坏帧、B/C 主动断开/空闲超时以及非法 CSV/config/数据库副本分别由独立脚本生成。执行时必须使用测试数据库或独立输入目录，不能用损坏副本覆盖运行数据；预期包括日志时间/对象可追溯、连接状态转红、非阻塞错误弹窗以及主界面继续运行。

## 原文要求的最终提交

- 三人完整源码、依赖安装和启动说明；不同电脑独立运行，局域网 TCP 联调。
- 系统说明和个人实际完成工作；设备/场景参数。
- 共同接口文档：名称、单位、范围、周期和报文示例。
- 单片机源码、烧录说明、无线与接线说明、传输协议（帧格式和字段）。
- 测试至少覆盖无风、适宜风速、高风、低负荷、高负荷、柴发上下限。
- 典型曲线/截图还原至少一轮完整闭环。

七项验收：功能完整性、接口一致性、运行合理性、数据库读写、硬件参与性、可观察与追溯、团队协作。团队应能说明接口修改过程与联调问题。
