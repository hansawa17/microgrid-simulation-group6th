# 下午现场验收演示脚本

## 到场前（15 分钟）

1. 三机 `git checkout v1.0.2`，记录 `git rev-parse HEAD`；各自用 Python 3.11 启动。
2. CubeIDE Clean/Build 0 error，烧录；记录 A WLAN IPv4、端口 5000、COM 号，不记密码。
3. 清理上次演示进程，但保留需要展示的历史；确认高风场景包含 `wind_speed_mps >= 25`。

## 主演示（10–15 分钟）

1. A：展示开始/结束/步长、风速/负荷双曲线、TCP 端点、四遥与历史；启动仿真。
2. B：连 A，展示 1 s 采集/5 s 调度、默认闭环、目标与 actual 分开。
3. C：连 COM，展示 STM32 获得 A state、`$WIND2`、参数回读、A IP；展示真实 MCU，不开 mock。
4. 闭环：按一个 `session/step/seq` 追踪 A state → B dispatch → C wind_action → A next state，对照三个本地数据库。
5. 曲线热更新：A 保持 running，拖动一个风速或负荷点，点“应用曲线到仿真”；说明 CSV 保存按钮仍独立，新值下一步生效且进程不中断。
6. 工况：顺次跳到无风、正常风、`>=25 m/s` 高风、低负荷、高负荷，解释风机禁运、柴发最小/最大与 unserved/surplus。
7. 评价：B 展示五项 EMS 评分与风机执行评价，数据不足时说明不伪造分数。

## 故障演示（5 分钟）

1. 在测试机对 B 运行 abrupt 故障注入；A 连接标识变红、弹出非阻塞告警，仿真仍运行。
2. 断开 B 网络后恢复；观察 B 退避重连和全量 state 恢复。
3. 断 ESP8266 供电或热点，再恢复；不按 MCU reset，记录自动恢复耗时。
4. 拔出 C USB 数据线再插回；COM 号未变时应自动重开，变号时在 GUI 重选。
5. 重启 A TCP；确认 B 和 STM32 C 均恢复，不重新烧录固件。

## 现场快速排障

- B/C 都连不上：先在 A 查监听地址/端口，再查 WLAN IPv4、防火墙和热点隔离。
- B 可连、C 不可：查 C 界面回读的 A IP，查 ESP8266 供电/串口，等待至少三个失败周期触发软复位。
- C 串口不恢复：确认 Windows 设备管理器中 COM 号是否变化；变化则重选，不需重烧固件。
- 现场出现不可恢复故障：保留 A/B/C 日志、固件串口输出、网络时间和当前 SHA，不用 mock 掩盖。
