# 网络联调

## 局域网/手机热点

A 电脑监听 `0.0.0.0:5000`（5000 为项目草案端口），B 与 STM32 连接 A 的实际 WLAN IPv4 地址。客户端不得连接 0.0.0.0。每个设备有各自 IP，不要设置成相同地址。

1. A、B 和 Wi-Fi 模块加入同一热点；先确认模块支持热点所用频段及安全方式。
2. A 电脑运行 `ipconfig`，查 WLAN IPv4，不要误用 VPN 或虚拟网卡地址。
3. 将该地址填入各客户端的本地配置；手机热点 DHCP 租约变化、重连或重启后重新检查。
4. A 服务启动后，B 在 PowerShell 执行 `Test-NetConnection <A的IP> -Port 5000`。只 ping 不足以证明端口可用。
5. 若失败，检查服务是否启动、监听地址、Windows 防火墙入站规则和热点客户端互通。仅放行所需程序/端口，不关闭整个防火墙。
6. 测试单片机连接，再进行应用报文测试。热点客户端隔离是否存在要实测，不能假定所有手机都支持。

`common/config.example.json` 默认 client 地址 127.0.0.1 仅用于单电脑测试。多设备时必须替换。局域网模式无需公网 IP 或端口映射。
真实 SSID/密码在各自本地配置或模块配置中管理，不提交固件中的硬编码密码。自动发现和固定地址绑定不是当前已实现功能。

## 公网 raw TCP 穿透

跨网络联调可在 A 电脑运行支持原始 TCP 的内网穿透客户端，将 `<public_host>:<public_port>` 映射到 A 本机 `127.0.0.1:5000`。B 与 STM32/Wi-Fi 模块直接连接公网端点；C 上位机仍只通过 UART 连接 STM32。

穿透服务必须支持普通 TCP 客户端、长连接及固定公网端点；域名解析和 TLS 能力需按实际 Wi-Fi 模块确认。当前 v1 协议没有认证与加密，禁止长期暴露无访问控制的公网端口。详细方案见 `tcp-interface-design.md`。
