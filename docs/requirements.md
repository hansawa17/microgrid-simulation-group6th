# 作业理解与实现边界

来源：《软硬件编程综合》课程大作业（南极考察站微电网智能调控系统），本次新上传 PDF。以下按原文章节核对；使用章节号定位，课程原文优先。

## 基本任务

以风电、柴油机和负荷构成孤立微电网，完成状态采集 → 调度 → 控制动作 → 实际仿真 → 状态反馈。
基础范围是单风机、柴发与负荷；原文第四节将光伏、储能、多机组、PI/复杂控制、燃油统计和更丰富可视化列为选做。

| 模块 | 输入 | 计算/动作 | 输出 |
|---|---|---|---|
| A | 独立风速/负荷场景、B 目标、C 动作 | 按物理模型和设备约束推进仿真 | 风速、负荷、风柴实际功率、状态、功率不平衡 |
| B | A 状态及参数 | 风电优先、柴发补偿、检查备用与上下限 | 风柴功率目标及调度启停请求 |
| C 单片机 | A 风速、风机目标、实际功率与桨距 | 保护判断、启停与桨距控制 | 风机启停/桨距动作 |
| C 上位机 | 单片机状态、用户配置 | 数据存储、展示、历史查询与参数管理 | 串口参数/模式回写 |

## 不能混淆的语义

- 风速与负荷是不同场景输入。不得仅凭风速计算用户负荷；random 可以生成测试场景，但不替代曲线读取功能。
- B 返回“希望发多少电”，不是实际发电量。
- C 返回“如何控制风机”，不是改变用户负荷的命令。
- A 根据风速、动作和模型计算实际功率。柴油机动态/补偿规则须约定，不能默认无限且瞬时补偿。
- 定义功率不平衡 `load - wind_actual - diesel_actual`：正值为缺电，负值为过剩。分别记录而非截断为零。
- 开环仅计算展示，闭环才发送控制；B 和 C 各自模式的组合行为需统一。

## 课程知识落地

Python 类封装设备、状态和数据访问；函数分离读取、计算与写回。A/B 的计算和通信采用独立进程、各自读写本地库。Qt 信号槽处理交互，定时刷新，耗时工作不放 GUI 主线程。
SQLite 管理参数、当前状态、指令、历史和日志。网络使用 socket；STM32 使用 UART 缓冲与中断、主循环解析以及定时器/HAL_GetTick 调度与超时判断。

原文 3.1/3.2 的周期：A 每 1 s 获取仿真参数并推进；B 通信每 1 s 请求变化量、每 1 s 检查指令更新；B 核心每 1 s 读取调度参数，采集周期默认 1 s、调度周期默认 5 s。B 模式默认闭环。仿真步长不等于执行周期，仿真时间与现实接收时间分别记录。
